# Comment ratchet

`scripts/comment_ratchet.py` is a baseline-and-ratchet stage for the pre-ship gate. It counts `#NNN` issue references inside product-code **comments**, per file, compares them with a committed baseline, and **fails when a file's count rises**. Existing history comments never block work; they cannot grow either.

The convention it enforces (a comment states why the code is the way it is now; how it got there lives in the issue, the PR and `git log`) is owned by the fleet-wide global instructions. This page does not restate the rule text; it documents the mechanism. It reuses the shape of the [static-analysis ratchet](static-ratchet.md): an opt-in `.fleet.toml` table, a committed baseline, the same flags, and exit 3 for "not confirmed".

## What is counted

Only comment text, extracted by a real scanner for each language. A regex over raw source lines would count strings and URLs.

| Files | Comments | Not counted |
|---|---|---|
| `.py` | stdlib `tokenize`, `COMMENT` tokens | string, f-string and docstring content |
| `.js` `.mjs` `.cjs` | `//` and `/* */` | single/double-quoted strings, template literals (including inside `${}`), regex literals |
| `.css` | `/* */` | strings, unquoted `url(...)` |
| `.ps1` `.psm1` | `#` line comments (at a token start), `<# #>` blocks, including inside `$( )` | single- and double-quoted strings, here-strings, a mid-word `#` (a variable name followed straight away by `#` and digits) |

A **reference** is `#` plus one to five digits, not preceded by `&` or `#`, ending on a word boundary. A reference to another repo's issue (`repo#<number>`, `owner/repo#<number>`) counts too (the same smell). `https://...` URLs inside a comment are blanked first, so an anchor never counts. Several references on one line count separately. Counting is per **reference**, not per comment line, and per **file**: a new reference in one file cannot hide behind a removal in another.

Docstrings are string tokens, not comments, and HTML (`<script>`, `<!-- -->`) is not scanned. Both are out of scope.

### Known false positive and blind spot

- **Digit-only hex colour in a CSS comment.** A grey written as `#` plus three digits inside a comment counts as a reference, because it has the same shape as an issue reference. A colour with a letter (`#21262d`, `#fff`) never matches, and the same value in a declaration (outside a comment) is not counted. Write the token name in the comment instead. A test pins this.
- **A JS regex literal directly after `)`** (`if (x) /re/.test(y)`) is read as a division, because the scanner decides regex-versus-divide from the previous token. It cannot hide a comment; the realistic failure (a quote inside the regex opening a string that never closes) is exit 3, not a wrong count. A test pins both.

## Scope

Files come from `git ls-files`, spawned with `GIT_OPTIONAL_LOCKS=0`, so ignored, generated and environment folders never appear. Product code only. Always excluded: `tests/`, `test_*.py`, `*_test.py`, `conftest.py`, `*.test.js`, `*.min.*`, `node_modules`, `.venv`, `venv`, `__pycache__`, and any file whose first five lines contain `DO NOT EDIT` or `@generated` (case-sensitive: the header of a vendor-verbatim file says "Do NOT edit this file per-app", which is prose, not a generated marker).

**Vendored components are excluded automatically in an adopter**: the script reads every `dest` in the repo's own `.fleet.toml` `[vendored]` table (a file or a folder), so the exclusion is never hand-maintained. The scaffold has no `[vendored]` table and owns its components, so they are in scope here.

## Exit codes

| Exit | Meaning | Gate |
|---|---|---|
| `0` | Pass (no file above its baseline), or the stage is **not enabled** | continues |
| `1` | A file's count rose, a new file carries references, or the baseline file is missing | fails |
| `2` | Bad `[comment_ratchet]` table, unreadable baseline, bad arguments | fails |
| `3` | **NOT CONFIRMED**: `git` unusable, or a file could not be scanned (unterminated string, comment, template or here-string; a Python file `tokenize` rejects; bytes that are not UTF-8). The message names the file. | fails |

Exit 3 is its own state and never folded into a pass or a clean tree. An unscannable file is never skipped. A file whose count fell, or that disappeared, passes and prints `N file(s) are below the baseline -- run --update-baseline`.

## The baseline file

Committed, sorted JSON, one entry per line, keyed by repo-relative path, with no line numbers so edits elsewhere in a file never churn it:

```json
{
  "version": 1,
  "entries": [
    {"key": "app/webapp/static/app.js", "count": 12},
    {"key": "src/config.py", "count": 2}
  ]
}
```

A file not in the baseline may not appear with a count above 0. The cost: moving or renaming a file that carries references reads as a new file, resolved with the explicit `--allow-additions` (visible in review).

## Modes

```
python scripts/comment_ratchet.py                                   # check (what the gate runs)
python scripts/comment_ratchet.py --init                            # first baseline; refuses to overwrite
python scripts/comment_ratchet.py --update-baseline                 # lower or drop entries; exit 1 + write nothing if any count rose
python scripts/comment_ratchet.py --update-baseline --allow-additions   # the explicit flag that raises or adds entries
```

A failing check names each file with its count and baseline, and lists every reference in it with its line. The fix is to reword the comment (state the why in words); raising the baseline needs `--allow-additions` and shows in review as changed lines in the baseline file.

## Adopting it (opt-in per repo)

Re-vendoring the script never breaks a repo that has not opted in: an absent `[comment_ratchet]` table, or `enabled = false`, prints `comment ratchet: not enabled` and exits 0 (declared, not inferred).

1. Vendor `scripts/comment_ratchet.py` byte-for-byte (`/propagate-vendored comment_ratchet`; manifest key `comment_ratchet`), and declare it in the repo's `[vendored]` table. It is stdlib-only and needs Python 3.11+ (`tomllib`).
2. Add to the repo's own `.fleet.toml`:

   ```toml
   [comment_ratchet]
   enabled  = true
   baseline = ".comment-ratchet-baseline.json"   # default
   include  = ["app/", "src/"]                    # path prefixes; default: the whole tree
   exclude  = ["**/generated/**"]                 # globs, added to the built-in set
   ```

   `exclude` globs are anchored at the repo root; `**/` means "any depth".
3. Run `python scripts/comment_ratchet.py --init` and commit the baseline. Review it: the first baseline records all existing debt.
4. Add a gate stage that runs `python scripts/comment_ratchet.py` and fails on any non-zero exit. The scaffold's `scripts/verify-before-ship.ps1` places it after the static ratchet and before `mypy`. **Do not path-route it**: a count needs the whole tree.
5. If the repo uses diff-proportionate e2e routing, add a `tier = "none"` rule for the baseline file to `.fleet.toml` `[e2e]` (the file at the repo root otherwise fails safe to the full browser suite) and a matching assertion in `tests/test_classify_e2e.py`.

The script spawns `git` with `CREATE_NO_WINDOW`, derived locally (it is vendor-verbatim, so it cannot import `src/no_window.py`).

The vendored ratchets share config-loading and glob helpers, because each vendored file must be self-contained. `static_ratchet.py` leaves every `[vendored]` destination out of its duplicate check, so an adopter has nothing to baseline for them. The scaffold has no `[vendored]` table, and its `.static-ratchet-baseline.json` still carries those pairs because it owns the sources.

## Cost

A read-only dry run over a ~280-file Python/JS/CSS/PowerShell adopter (24 vendored destinations excluded) scanned every file without a "not confirmed" and took about **0.5 s**, so there is nothing to tune. It counted roughly 2,400 references (about 660 in Python, 1,330 in JS, 350 in CSS, 40 in PowerShell), which is what that adopter's first `--init` will record. This scaffold's own baseline is empty, vendored components included.

## Tests

`tests/ratchets/test_comment_ratchet.py`: counting per language on fixture strings (including the strings, templates, regex literals, URLs and entities that must not count, and the two pinned limitations above), scope and exclusions, and every mode and exit code on throwaway git repos. A missing prerequisite is a hard failure there, never `pytest.skip`. The scaffold's own gate stage doubles as the guard that its committed baseline is current.
